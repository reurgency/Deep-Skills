The problem

AI agents are confident.
Confidence is not evidence.

Any agent can generate a plausible diff. The hard part is everything around it — and it's exactly where unattended AI work quietly falls apart:

// nobody asked "should we?"

It builds things that shouldn't exist

Agents execute whatever they're told. A misdiagnosed cause or an unsound premise gets faithfully — and expensively — implemented.

// reviewer == author

It marks its own homework

An agent reviewing its own output shares its own blind spots. "Looks good to me" from the same context that wrote the code is theater, not review.

// tests pass ≠ it works

"Tests green" gets confused with "done"

Typecheck and unit tests can't tell you the change behaves on real data, survives the last mile to the user, or is even live after merge.

// what happened here?

There's no paper trail

When a run ends, all you have is a diff and a chat transcript. No record of what was reviewed, what was deferred, what was rejected — or why.

How it works

A real engineering pipeline, not a longer prompt.

One invocation walks your change through six specialized stages. Every stage runs as a fresh, independent agent that communicates only through durable artifacts — reviewers never see the author's reasoning, so they can't inherit its blind spots. Progress is verified by checking the artifacts themselves, never by trusting an agent's summary.

01

Plan

Scoped, evidence-based plan — with a gate that can kill unsound work before a line is written.

02

Plan review

Independent agents critique the plan against your codebase and cite every finding.

03

Implement

Phase-by-phase build in an isolated worktree. Never commits failing code. Never touches main.

04

Code review

Adversarial multi-lens review of the diff. Findings are severity-scored and verified before they count.

05

Fix

Diagnosis-first repairs at the root cause. A separate agent proves each fix — or it's reverted.

06

Docs

A machine-readable map of what was built. Every claim anchored to file:line or it doesn't publish.

└─ stages 04–05 loop until they converge: fewer findings every round, capped by your rigor level — never an infinite review spiral.

The rigor dial

Pay for exactly as much certainty as the change deserves.

Full ceremony on a throwaway spike is waste. A light touch on a data migration is reckless. One dial — --rigor — selects the stages, the review depth, and the convergence bar. Levels are data, not prose: drop a rigor-map.json in your repo to reshape them or add your own.

The philosophy

Evidence over vibes, at every stage.

Deep Rigor is a powerful combination of empirical verification and structured orchestration — every claim in the pipeline is backed by something that ran, measured, or resolved, not by an agent's say-so.

⚖️

It can tell you "no"

Before planning, the pipeline evaluates whether the change is sound and worth building. If the premise fails on real evidence, you get the finding and the receipts — not a beautifully executed mistake.

📏

Measure before reasoning

When a plan hinges on an empirical question — is it actually slow? will this over-match? — the pipeline runs the five-minute probe on real data first, and plans from the measurement.

🥊

Adversarial by design

Review agents are briefed to refute, not to approve. Findings above the severity bar face a fresh verifier trying to knock them down; every survivor cites file:line. Refuted claims are kept on record, never silently dropped.

🔌

Verified against reality

Beyond typecheck and tests: run it on real data, print the actual rows, probe the latency, watch the real traffic. "Green" without an empirical proof of the core claim doesn't clear the bar at higher rigor.

🚀

Live means proven live

Every plan states its activation path — restart, reload, reconnect, migration — up front. After merge, the pipeline confirms the change is actually running and shows the before/after. No more stale-build victory laps.

🛟

Risky mutations ship dark

Changes that touch live data go out behind an off-by-default flag with a logging dry-run. Reading the dry-run's real output is the go/no-go gate — before a single row changes.

Autonomy with guardrails

Walk away. It knows when to interrupt you.

All human interaction happens up front, in the planning window. After that the run is autonomous — and disciplined about your attention. It pings you for exactly four things: a blocker, a checkpoint you asked for, a budget ceiling, or completion. Everything else is a decision it makes and records.

  • Gates you place: "pause before implement" injects a human checkpoint into an otherwise hands-free run.
  • Budget ceilings: cap the spend; the run pauses cleanly between stages when it's crossed — resume, raise, or stop.
  • Crash-safe resume: pipeline state persists from launch. Re-invoke after any interruption and it picks up at the exact stage it left — never re-running finished work.
  • A full paper trail: plans, review findings, severity ledgers, deferred items, per-stage spend, and a final run report — durable artifacts your whole team can audit.

Built for the long haul

Big efforts. Many sessions. Zero amnesia.

Large work decomposes into dependency-ordered, independently-shippable slices — each one a full pipeline run, merged with your approval before the next begins. And because everything lives in artifacts, a fresh session inherits the whole state:

  • Plans are self-contained. No stage depends on chat history; any agent, any day, can pick up where the last one stopped.
  • The plan is a hypothesis. When a measurement breaks a slice's premise, the sequence changes — the pipeline never executes a now-wrong plan because it was the plan.
  • Rejected approaches stay rejected. What was tried, killed, and why is on the record — so no future session burns a day rediscovering it.
  • It gets better as you use it. Learned, human-approved improvements ship as data the pipeline loads at runtime — your process compounds without anyone rewriting it.
"Done" doesn't mean the agent said so.
It means reviewed by fresh eyes, proven on real data, live in production — with the receipts filed.

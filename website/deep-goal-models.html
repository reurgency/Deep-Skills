Advanced · the conductor

How deep-goal picks models

Rigor decides which stages run. One more choice - --max - decides how smart the models get. From those two, every stage and every helper agent gets a named model, set explicitly. You see the whole list on the launch card before anything runs.

Back to deep-goal Jump to the stage table

In plain words

Three levels, one choice, a named model everywhere

There are three model levels - smartest, smarter, and smart - and each is pinned to specific models. You choose the highest level a run may use with --max (or answer the question deep-goal asks at launch). A fixed table then says which model each stage runs on, and each stage's own helpers pick their models the same way the skill does when you run it on its own.

🧠

Your current model is not the model your stages run on. The model you're chatting in runs deep-goal itself and interactive planning, and it sets the suggested --max. Everything deep-goal launches - plan review, implementation, code review, bug fixing, docs - runs on the model the table names, which can be smarter than your session. That's intended.

The levels

Smartest, smarter, smart

Each level names a current model and the previous one to fall back to. A run stays in your session's model family - a Claude session uses the Claude column, a GPT session the GPT column.

Level Claude GPT
smartestFable 5.2 (then Fable 5)Astra-6 (then GPT-5.6 Sol)
smarterOpus 5.5 (then Opus 5)GPT-6-Sol (then GPT-5.6 Terra)
smartSonnet 5.5 (then Sonnet 5)GPT-6.1-Terra (then GPT-5.6 Luna)

Smart is the lowest level any agent uses - small models (Haiku, GPT mini/nano) never run, because every job in the pipeline is reasoning work. GPT names are display names until the host model IDs are confirmed. The exact IDs live in the skills' shared model map.

Your current model

What the model you're chatting in actually does

⚙

Runs deep-goal itself

The conductor - sequencing stages, checking artifacts, writing the run report - runs in your session, on your current model.

💬

Runs interactive planning

At mvp and prod you answer planning questions, so planning runs inline in your session. If your model is below the planning level you chose, the launch card suggests switching with /model (or your assistant's model picker) first.

🎯

Sets the suggested --max

Leave --max off and deep-goal asks, recommending your current model's level - Opus 5.5 suggests smarter, Fable 5.2 suggests smartest. You can pick higher or lower.

On assistants that can't run background agents (Codex, Cursor, and Copilot today), each stage's lead also runs in your session; the helper agents inside a stage still use the level you chose, and the launch card says so.

Code review with a single reviewer (poc, mvp) runs on the stage's model - Fable 5.2 at smartest. The main bug-hunting finders (removed behavior, write-to-read tracing, last-mile wiring, frozen state) found every serious bug in calibration, so they stay on the stage's model. A finding rated 5 that a verifier raises to 6 or more is re-checked on the stage's model. --mega puts every finder and verifier on the stage's model.

Bug fix: the smartest model you allow writes the diagnosis; the stage's model implements exactly that. The proof runs on the --max model whenever a defect in the cluster is rated 5 or higher (on the stage's model - Opus 5.5 - when every defect is rated below 5).

Two honest exceptions

Where reality bends the table - openly

💬

Interactive planning runs on your session

A background agent can't ask you questions, so mvp/prod planning runs inline while you're present - on the model you're chatting in. If that's below the planning level you chose, the launch card says so and suggests switching with /model before you launch.

⏷

Can't reach a model? Older first, then a level down

If your plan or org blocks a model, that stage first tries the same level's previous model (Fable 5 for Fable 5.2), then the next level down (Opus 5.5) - never below smart, never a small model. The pipeline file and the run report record what actually ran, e.g. “smartest ran on Fable 5 (no Fable 5.2 access).”

Make it yours

Repin a model, or move a stage's level

Drop a .deep-skills/model-map.json at your repo root. List only the keys you want to change - it merges over the shipped map, applies to deep-goal and every deep-skills skill run on its own, and is checked at launch: an invalid file stops the run before anything is written, naming the key and the values it accepts.

Example - when you choose --max=smartest, write docs on Opus 5.5 (smarter) instead of Sonnet 5.5:

{"stages":{"smartest":{"docs":"smarter"}}}

Under ladder you can repin a level to different models; under stages you can move a stage to another level, as long as it doesn't go above the --max it sits under (stages.smart.docs = "smartest" is refused). The helper assignments inside each skill aren't configurable.
